## 3. NOT fixed here — flagged with reasons + next steps

### 3a. LSTM checkpoints are stale / inconsistent — **needs retrain (blocked)**
- All `lstm_detector/checkpoints/*_meta.json` report `feature_dim: 5`, but the code is now `6` → the committed `.pt` **will not load** into the current model.
- `theta_ae_urban.txt` (0.002935) ≠ the meta θ_ae (0.000377) — artifacts from different runs.
- **Blocker:** only `urban` training data is in the repo; **rural/highway training CSVs are missing**, so the rural/highway models cannot be regenerated here.
- **Next step (owner):** supply rural/highway clean CSVs, then retrain all three so meta/scaler/θ_ae/`.pt` all agree on `feature_dim=6`.

### 3b. Fusion still uses the LEGACY models — **left as-is on purpose**
`analytics/ml/train_fusion.py` imports the legacy `analytics/ml/gat_detector.py` +
`lstm_ae.py` and loads from `analytics/ml/models/`, not the new `gat_detector/` /
`lstm_detector/` packages.
- **Why I did NOT rewire it now:** it cannot be validated until 3a (retrain) is done,
  and the new GAT `S_i` is an unbounded L2 norm while fusion expects a `[0,1]` score.
  Shipping an untested rewrite would be a landmine. The legacy wiring currently
  works and is `[0,1]`-normalised, so leaving it is the safer state.
- **Exact rewire steps (do AFTER 3a):**
  1. Import the new GAT encoder + locked stats (`gat_detector.score.load_assets`) and
     the new per-scenario LSTM (`lstm_detector` model + `scaler_<s>.json` + `theta_ae_<s>.txt`).
  2. Match the new GAT feature layout `[x, y, speed, head_sin, head_cos, accel]`
     (sin/cos heading) — different from the legacy `[…, heading, …, tau]`.
  3. Normalise the new GAT `S_i` to `[0,1]` before fusion (it is not bounded).
  4. Keep `score_fusion.learn_weights` unchanged — it already matches the paper.

### 3c. GAT z-score path underperforms — **supervisor decision**
Documented in `gat_detector/README.md §5`: the paper's discard-head + z-score path
scored MCC ≈ −0.16 (vs ≈ 0.64 for the trained head). **Do not silently switch to the
head** — this is a design decision for the supervisor.

### 3d. RSU nodes missing from GAT graph — **design / supervisor**
Paper (`sec:gat_design`) is a **vehicle–RSU** graph; code builds vehicle-only. The
`# RSU EXTENSION POINT` in `dataset.py` marks where to add RSU nodes + masking.

### 3e. τ_i (trust) not wired — **cross-component**
Both detectors default trust to a constant 1.0 (no trust column in the beacon CSV).
Real on-chain trust must be exported into the feature CSV to match the paper's 6-dim set.

### 3f. Data provenance — suburban/highway (GAT) and rural/highway (LSTM) are synthetic / missing
Real NS-3/SUMO beacon exports are required for all three scenarios before any
checkpoint is used as Task-6 evidence.
